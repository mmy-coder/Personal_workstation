# Personal OS / 个人工作台

一个本地、单用户的个人数字系统，用来安排时间、记录物品、管理订阅和保存思考。所有核心记录持久化至 SQLite；初始数据库为空，没有自动注入示例数据。

### 可选示例数据

执行 `npm run db:demo` 可添加 39 条日程、16 件物品、12 项订阅和 12 篇笔记。日期相对于执行当天生成，覆盖上周、本周、下周、跨天安排、不同完成与使用状态、续费提醒，以及 Markdown 和标签。

这些记录均有“示例”标记，订阅金额为虚构验收数据；写入后会正常参与统计。脚本只新增固定 ID 的记录，不清空已有数据；重复运行不会覆盖已有记录或你的修改。2026 年 10 月 9 日已按用户要求在当前正式库执行一次。

## 快速启动

需要 Node.js **22.15+**（推荐 Node.js 24 LTS）与 npm。

```bash
npm ci
cp .env.example .env
npm run db:generate
npm run db:init
npm run dev
```

打开 <http://127.0.0.1:3000>。当前交付目录已安装依赖、生成 Prisma Client 并初始化正式数据库，可直接执行 `npm run dev`。

`db:init` 会创建缺失的数据库文件并应用提交在 `prisma/migrations` 中的迁移；重复运行不会清空已有记录。`.env` 内默认配置：

```dotenv
DATABASE_URL="file:./personal.db"
```

相对路径以 `prisma/` 为基准，默认文件是 `prisma/personal.db`。环境变量可覆盖 `.env` 中的值。

生产方式运行：

```bash
npm run db:init
npm run build
npm start
```

生产构建使用 Next.js 官方支持的 Webpack 后端，避免部分受限 macOS 环境中 Turbopack CSS 进程通信失败。开发模式仍使用 Turbopack。

## 已实现功能

- **总览 `/`**：六项数据库统计、最近七天工作时长、分类环图、每日计划/完成对照、订阅实际付款历史（无流水时显示当月预计付款）；时间分配与每日对照可切换本周/本月。今日安排、未来任务、七天续费提醒、最近三条笔记与物品均可打开详情。
- **时间日历 `/calendar`**：周一至周日、00:00–24:00 的完整时间网格，半小时点击建档，跨小时/跨天展示，周切换、今天和当前时间提示、固定日期表头。支持新增/编辑/删除/完成、桌面拖拽改期、底边拖动调整时长。重叠日程分栏，保存冲突须再次确认。紧凑统计栏与时间轴减少滚动；日期旁可直接新增，点击日期放大为日视图并查看当天完整列表，支持日期跳转与上午／下午／晚间定位，周／日视图会被记住。
- **资产与订阅 `/assets`**：两个标签页、完整表单、CRUD、文本搜索、分类/状态筛选和排序；物品支持图片 URL、可空购买金额/日期；数量及购买金额分类图。订阅支持月付/年付、活跃月均/年化成本、续费提醒和分类成本环图；确认续费会原子保存实际付款并推进续费日期，支持付款更正和删除。
- **感悟笔记 `/journal`**：标题可空、正文必填、Markdown/GFM 预览、标签、全文搜索、每页 12 篇的分页列表、排序、置顶、收藏、创建/修改时间、完整编辑与删除。未提交输入自动存为当前浏览器的独立窗口草稿，同窗口重新打开或刷新后会恢复；改回原文或保存成功后清理草稿。草稿记录基准版本，发现原笔记已更新或删除时可另存新笔记；旧版草稿和其他窗口的草稿可从“找回其他草稿”恢复为独立副本。保存或放弃当前稿件只清理当前窗口的草稿。
- **草稿箱**：集中预览本机草稿，原笔记删除后仍可另存新笔记；重复整理须确认，保留最新副本并跳过正在编辑的草稿。恢复另存后仍保留来源草稿，确认不再需要时可手动清理。
- **页面记忆**：日历周和分类、资产标签页与筛选、笔记搜索与排序写入网址，并在当前浏览器会话中记忆；日历滚动位置及列表页面位置也会恢复。
- **通用**：浅色/深色主题持久化、移动端折叠菜单、键盘焦点和弹窗焦点管理、加载/错误/空状态、删除确认、操作反馈、JSON 全量导出、校验与合并恢复。

## 数据口径

### 时间

日历按**浏览器本地时区**输入和显示，数据库保存 UTC 时间点。日历周以周一开始，范围采用左闭右开区间。跨天、跨周、跨月日程按与统计范围相交的时长计算。

- 计划时长：范围内所有日程的时长之和。
- 已完成时长：被标记完成的日程时长之和。
- 已完成工作时长：仅“工作”分类中被标记完成的时长。
- 完成率：全部分类已完成时长 / 全部分类计划时长；分母为零显示 `—`。
- 时间冲突可由用户确认后保存，统计按每条日程累加，不把重叠时段合并。因此一天计划时长允许大于 24 小时。
- “完成”代表整条日程完成，当前不包含计时器或部分完成进度。

### 金额与订阅

购买价格和每期付款金额以**整数分**存储，校验限制为非负、最多两位小数；空购买价格与 0 元不同。

- 物品累计购买金额包括所有状态下已填写的购买价格，**不代表当前资产市值**。
- 月付月均成本为原付款金额；年付月均成本为付款金额 / 12。均摊内部保留精度，最终显示时四舍五入到分。
- 年化成本为月付金额 × 12，或年付原金额。暂停、取消不计入活跃成本。
- 总览“本月订阅支出”是**按当前活跃订阅估算的当月应付款**，不是月均成本，也不是确认付款流水。
- 付款日期由下次续费日作为周期锚点推算；月付每月一次，年付每年对应月份一次；短月使用月底，不计开始日期前的付款。
- 点击活跃订阅旁的“确认续费”，核对实际金额、付款日期和下次续费日期后保存。每次只记一笔实际付款，不自动补记逾期历史；付款与日期更新在同一事务中完成。短月推进保留原付款日，例如 1 月 31 日 → 2 月 28 日 → 3 月 31 日。
- 有付款流水时，总览趋势图只按已记录的付款日期汇总实际金额；没有流水时只展示当前可计算的预计付款，**不生成虚假的历史趋势**。未记录月份不被解释为零支出。
- 付款保存当时的订阅名称和分类；修改价格或删除订阅不会修改历史付款。付款记录可以更正金额、日期和备注，或删除误录记录；这些操作不会自动回退订阅续费日期，需要另行核对。
- 过期只提醒核对，不自动认定已付款，不擅自推进日期。也可在编辑订阅中手动维护日期。

## 技术与结构

Next.js 16 App Router、React 19、TypeScript、Tailwind CSS 4、基于 shadcn/ui 模式的本地 Button/Dialog（Radix）、Lucide React、Recharts、Prisma 6、SQLite、Zod 4、react-markdown。

```text
prisma/schema.prisma       五个业务模型及内部恢复、请求记录表
prisma/migrations/         可重复部署的数据库迁移
src/app/                   四个页面与 REST Route Handlers
src/app/styles/            按布局、模块、表单与响应式拆分的样式
src/components/            日历、表单、图表、笔记和应用外壳
src/components/ui/         可维护的本地基础组件
src/lib/validation.ts      服务端权威输入校验与金额转换
src/lib/stats.ts           无 UI 依赖的统计和周期计算
src/lib/api.ts             CRUD、版本冲突保护与数据库记录转换
src/lib/queries.ts         时间范围查询、笔记分页及总览摘要
src/lib/backup.ts          备份文件格式与字段校验
src/app/api/backup/        恢复预览、事务恢复和恢复前自动副本
scripts/init-db.mjs        无损初始化 SQLite 文件与迁移
tests/*.test.ts            统计、边界、精度和草稿单元测试
tests/e2e/                 使用独立数据库的浏览器验收
```

五个业务模型为 `CalendarEvent`、`Item`、`Subscription`、`JournalEntry`、`SubscriptionPayment`；内部表 `BackupRestoreLink` 防止重复恢复，`MutationReceipt` 防止同一创建或续费请求被重复执行。笔记标签以 JSON 字符串存储在 SQLite，并在 API 边界转为数组。日期型字段采用 `YYYY-MM-DD`，避免购买日和续费日因时区转换偏移。

API：`GET /api/data` 获取完整数据（导出使用）；`GET/POST /api/{events|items|subscriptions|journals}`；`GET/PATCH/DELETE /api/{resource}/{id}`。

- 创建接口支持 `Idempotency-Key`，界面自动使用并在当前会话中保留未确认成功的请求标识；相同内容重试返回同一记录，复用标识提交不同内容返回 409。续费接口 `POST /api/subscriptions/{id}/renew` 必须带该标识。请求记录与业务写入使用同一事务。
- `GET /api/payments` 读取付款历史，`PATCH/DELETE /api/payments/{id}` 更正或删除；付款仅从确认续费入口创建。
- 每条记录都有整数 `version`。更新和删除必须发送 `If-Match: <version>` 请求头；缺失版本返回 428，版本冲突返回 409，成功更新后版本加一。数据库在同一条更新或删除语句中检查版本，避免两个窗口相互覆盖。
- PATCH 支持部分字段，与数据库当前记录合并后执行完整 Zod 校验。未知字段忽略。不存在的记录返回 404，输入错误返回 400，跨站写入返回 403。
- 界面使用 `GET /api/data?view=workspace&scope=dashboard|assets|journal|calendar&...` 按页面加载数据。总览只获取范围内日程、近期记录、统计和按月汇总的付款金额；资产页获取独立的全局统计及到期提醒；笔记页仅获取笔记统计与标签；日历通过独立范围接口读取日程。日期边界、当月日期和七天后的续费日期由浏览器按本地时区计算。省略 `scope` 的旧接口保持兼容，`GET /api/data` 始终完整导出。
- 物品、订阅和付款历史支持 `GET /api/{items|subscriptions|payments}?page=1`，每页 12 条，返回 `entries/total/page/pageSize`。资产列表支持 `q/category/status/sort` 服务端筛选和稳定排序，搜索延迟 200ms 发起请求；页码记入网址，筛选切换回到第一页，删除末页后自动回退。顶部总数、金额和分类图表独立计算，不受分页或筛选影响。付款记录只在订阅页加载，总览按所有付款记录汇总月份；不带 `page` 的读取接口仍返回完整数组。
- 日历使用 `GET /api/events?from=<ISO>&to=<ISO>` 查询与范围相交的日程；跨天日程不会漏掉。修改时间前重新查询冲突范围。
- 笔记列表使用 `GET /api/journals?page=1&q=关键词&tag=标签&sort=最近创建&favorite=false`，每页 12 条摘要，服务端搜索完整正文。点击后再获取全文，避免反复下载全部正文。总数、收藏数和本月新增数独立计算，不受分页影响。
- 日程、物品和订阅表单有未保存修改时，关闭弹窗会提供“继续编辑／放弃修改”，刷新或离开页面会触发浏览器提醒。保存期间锁定表单并防止重复提交；读取请求可取消且忽略过期结果。后台同步失败时保留已加载内容和正在编辑的表单，展示重试提示。
- 顶栏、总览与日历共享每 15 秒更新的本地时钟；跨日自动刷新统计范围，任务开始时刷新后续安排。保存后的列表更新统一由刷新结果触发，避免连续重复加载。
- 同浏览器窗口通过 BroadcastChannel 通知刷新，窗口重新获得焦点时也会重新读取；已有编辑内容不会被后台刷新替换。导出时始终重新读取完整数据库。

Prisma 工具链的 `deepmerge-ts` 已通过 npm override 升级至 8，修复其递归合并漏洞；初始化、生成客户端及构建均需作为升级回归检查。

## 备份与长期使用

- 设置面板新增“自动备份”：默认启用，每 24 小时一次，保留最近 7 份；间隔可设为 1–168 小时，保留数量可设为 1–30 份。服务运行时每分钟检查是否到期，启动后约 5 秒补做已到期的备份；关闭服务或电脑休眠期间不会执行。设置 `DISABLE_AUTO_BACKUP=1` 可禁用后台调度（测试环境已设置），不影响手动备份。
- 自动及“立即备份”生成的 JSON 位于数据库旁的 `backups/<数据库文件名>/automatic/`，默认 `prisma/backups/personal.db/automatic/`；设置保存在同目录。可在“本机备份”列表下载，再通过原有恢复入口预览和补回记录。降低保留数量后，下次成功创建备份时开始轮换；不会清理恢复前安全副本。新备份校验并保存成功后才删除超额旧副本，失败时保留已有备份并显示错误。备份沿用 20 MB、每类最多 10,000 条的限制，超出时请复制完整 SQLite 文件。文件在本机，建议定期另存至其他设备。
- 设置面板可导出全部五类业务记录（含实际付款）为 JSON；通过“从备份恢复 → 选择备份”上传该文件，查看各类记录的“将恢复／跳过已有”数量，勾选核对确认后执行。
- 恢复采用**合并补缺**：同 ID 已有记录保留当前值；此前已恢复且仍存在的记录也跳过。不会用旧备份覆盖当前修改，不会清空数据库。恢复的记录保留业务内容、创建和修改时间，使用新的内部 ID，避免旧窗口误写已恢复记录。
- 恢复支持本项目 `version: 1` 的完整 JSON 导出，最大 20 MB、每类最多 10,000 条；文件格式、金额、时间、正文与重复 ID 均先校验。兼容不含付款记录的旧版文件；恢复付款时会关联恢复后的订阅。JSON 不包含浏览器草稿、主题偏好、内部恢复映射和请求记录。
- 真正新增记录前，服务端自动在数据库旁的 `backups/<数据库文件名>/before-restore-*.json` 保存恢复前全量记录；默认路径为 `prisma/backups/personal.db/`。副本创建失败时不写数据库；数据库恢复或映射写入失败时整个事务回滚。执行结果显示副本路径。测试库副本保存在 `prisma/backups/e2e.db/`，与正式库隔离。
- 如需完整回到某一时刻，包括覆盖修改与恢复内部映射，请使用下面的 SQLite 文件备份；JSON 界面只补缺，不提供破坏性的覆盖恢复。
- **完整备份**：先停止应用，再复制 `prisma/personal.db` 到备份位置。恢复时先备份当前数据库、停止应用，再用所需备份替换该文件，执行 `npm run db:init` 后启动。
- 浏览器草稿未提交至数据库，清除浏览器站点数据会删除草稿；重要笔记请点击“保存笔记”。本地存储不可用时，页面会提示并在关闭未保存笔记前确认。
- 当前单用户版本默认只监听 `127.0.0.1`。如未来部署到公网，需要先增加身份认证、访问隔离以及数据库备份策略。

## 批量管理与自动检查

- 资产页点击“批量管理本页”，可多选当前页物品或订阅修改分类、状态或删除；日历点击“批量管理日程”，可处理当前日／周及分类筛选范围内的日程，修改分类、完成状态或删除。每批最多 100 条，超出时请缩小日历范围；每次均需勾选核对确认，删除不可直接撤销，历史付款仍保留。
- 批量操作保留打开窗口时的版本。`POST /api/bulk` 必须带 `Idempotency-Key`，正文包含 `resource`、`records: [{id, version}]` 和 `operation: {action, value?}`；动作支持 `category/status/complete/delete`。任一记录已被其他窗口修改或删除时，整个事务回滚并返回 409；相同请求重试不会重复执行。
- `.github/workflows/ci.yml` 在推送、Pull Request 或手动触发时执行依赖安装、数据库初始化、单元测试、生产构建、类型检查和 Chrome 浏览器验收。使用独立测试数据库，不含个人数据；同一分支的新任务会取消旧任务。提交并推送该文件后，可在 GitHub 的 Actions 页面查看结果。本地运行成功不代表远端工作流已经执行。

迁移 PostgreSQL 时应更换 Prisma provider 并生成独立的新迁移，通过导出/导入迁移数据；SQLite 迁移 SQL 不能直接用在 PostgreSQL 上。增加账户时，为各模型加入 `userId` 外键和查询隔离，再开放云端访问。
